## 2. 도출한 갭 3종

### 갭 1. 형식 검증 누락 (구현 필요)

> 정본 요건 ② 세부설명: `필수 필드·형식 검증`
> 공지 §2: "값은 있으나 정수·날짜 등 형식 해석에 실패하면 프로그램을 중단하지 말고
> `확인 필요`와 실패 이유를 표시합니다."

현재 구현은 `missing_required`에서 **공란만** 검사한다. 단가에 문자열이 들어오거나
적용일이 `2026-13-45`처럼 해석 불가능한 값이어도 통과한다.
제공 20건은 전부 정상값이라 자체 테스트로는 드러나지 않는 구멍이었다.

**대응**: `exception_flags` 4종은 그대로 두고 별도 필드로 형식 오류를 다룬다.
공지가 "예외 4종 탐지 규칙과 제공 20건 정답을 변경하지 않습니다"라고 명시했으므로
5번째 플래그를 추가하면 정답 대조가 흔들린다. 상태는 `확인 필요`로 보내고
실패 이유는 상세 화면에 표시한다.

### 갭 2. 브랜드·UI 가이드 미반영 (구현 필요)

> 정본 4번 시트: 서비스 표기 = ComfoziAI 구매 증빙 인박스 /
> 기본 컬러 = Comfozi Navy `#1A3356`, Gold `#C89C4A`, Surface `#F6F4F0` / desktop 우선

현재 화면은 기본 팔레트를 쓰고 있고 서비스 표기도 `구매 자료 검토함`이다.
화려한 디자인은 요구되지 않지만, 지정된 컬러와 표기를 쓰지 않은 것은 별개 문제다.

**대응**: 3색을 헤더·주요 버튼·배경에 적용하고, 제목을 `ComfoziAI 구매 증빙 인박스`로
바꾸되 OT 발표에서 쓰인 `구매 자료 검토함`을 부제로 병기한다.
desktop 우선은 현재 레이아웃이 이미 충족한다.

### 갭 3. JSON·CSV 샘플 산출물 부재 (산출 필요)

> 정본 4번 시트 필수 인계물: ① 구동 URL ② 소스코드 전체 ③ 실행 README
> ④ **JSON+CSV 샘플·필드 설명** ⑤ 미지원·실패 시도·알려진 오류

④가 "필드 설명"만이 아니라 "샘플"을 포함한다. README에 필드표는 있으나
실제 출력 파일이 없다.

**대응**: 내보내기 구현 시 20건을 승인해 실제 출력 파일 2종을 산출물로 남긴다.

## 5. 후속 작업

1. 브랜드 가이드 반영 (갭 2)
2. 필수값·형식 검증 (갭 1)
3. JSON·CSV 내보내기와 샘플 산출 (갭 3)
4. 발표자료 목차를 정성 평가 5축으로 구성

정성 평가 5축은 다음과 같다. 발표 구성의 기준으로 사용한다.

```
① 입력값과 구조화 후보의 관계가 이해되는지
② 검수 대기 이유와 원본 행 근거가 충분한지
③ 수정·승인·반려 및 변경 이력이 의사결정에 도움이 되는지
④ JSON·CSV 필드가 기존 ComfoziAI 앞단 설계에 활용 가능한지
⑤ 초급팀이 구현하지 못한 한계와 오류가 숨김없이 기록되는지
```
