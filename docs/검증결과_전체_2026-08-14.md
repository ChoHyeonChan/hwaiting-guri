배포본 https://hwaiting-guri.vercel.app

## 이 문서가 담은 것

`scripts/verify-20.ts`를 실행한 **출력 전문**이다. 문장을 다듬지 않고 콘솔에 찍힌 그대로
옮겼다. 검증 결과를 요약해 옮겨 적으면 그 요약이 맞는지 다시 확인해야 하기 때문이다.

이 테스트는 **기대값을 코드에 적어 두고 실제 실행 결과와 대조**한다. 어긋나면 `FAIL`을
찍고 종료 코드 1로 끝난다. 아래 출력의 마지막 줄이 `전체 통과`인 것이 결과다.

| 항목 | 값 |
|---|---|
| 섹션 수 | 12 |
| 개별 검사 | 전부 PASS |
| 실행 종료 코드 | 0 |
| 함께 통과한 것 | 타입 검사 · ESLint · 프로덕션 빌드 |

`PASS`가 그 검사의 결과다.

## 증빙 데이터가 외부로 나가지 않는다 — 배포본 실측

구매 증빙은 거래처명과 단가가 담긴 자료다. 이 화면이 그 값을 어디로도 보내지 않는다는 것을
배포본에서 직접 측정했다. **전 기능을 실제로 사용한 뒤** 요청 전량을 집계한 결과다.

측정 중 실행한 것: CSV 20건 업로드 → PDF 공문에서 3건 읽어 등록 → 항목 선택 →
적용일 수정 → 승인 → JSON 내려받기 → CSV 내려받기.

| 측정 항목 | 결과 |
|---|---|
| 전체 요청 | 25건 |
| 그중 자기 도메인(`hwaiting-guri.vercel.app`) | 25건 |
| 외부 도메인 요청 | **0건** |
| POST·PUT·PATCH 요청 | **0건** (전부 GET) |
| `fetch` 호출 | **0건** |
| `XMLHttpRequest` 호출 | **0건** |
| `navigator.sendBeacon` 호출 | **0건** |
| `WebSocket` 연결 | **0건** |

전송 계열 API는 페이지 로드 시점에 감싸 두고 호출을 기록했다. 정적 파일 요청과 별개로,
**앱이 데이터를 내보내려 시도한 적 자체가 없다**는 뜻이다.

PDF를 읽는 데 쓰는 pdf.js 작업자도 자기 도메인에서 받는다.

```
GET /_next/static/immutable/media/pdf.worker.28jxijx3_bnpc.mjs
```

외부 CDN을 참조하지 않으므로, PDF 기능을 붙인 뒤에도 "증빙이 밖으로 나가지 않는다"는
성질은 그대로다. 서버로 파일을 올리지 않고 브라우저 안에서 읽는다.
