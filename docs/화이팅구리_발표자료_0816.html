1팀의 차별점 — 합치지 않습니다, 판단할 근거를 만듭니다

가격 인상 공문을 자동으로 반영하면 빠릅니다. 그런데 틀렸을 때 아무도 모릅니다.
저희는 자동으로 합치지 않고, 사람이 판단할 수 있게 근거를 갖춰 보여주는 쪽을 택했습니다.

숫자 뒤를 봅니다

단가가 그대로여도 양이 줄었으면 오른 것입니다. 표에 적힌 숫자만 비교하지 않고, 규격이 바뀐 건을 따로 골라냅니다.

어디서 왔든 똑같이 검사합니다

파일로 올리든, 손으로 넣든, PDF 공문에서 읽어 오든 같은 검사를 거칩니다. 그래서 PDF로 넣은 건과 파일로 올린 건 사이의 중복도 잡힙니다.

근거 없이는 승인이 안 됩니다

문제가 남은 항목을 승인하려면 왜 괜찮은지 메모를 적어야 승인 버튼이 열립니다. 승인한 뒤 값을 고치면 승인이 저절로 풀립니다.

2담당자는 이렇게 씁니다

타겟은 가맹점 10~99개 규모 외식 프랜차이즈 본사의 구매 담당자입니다. 공급사에서 온 인상 공문을 정리해 시스템에 넣는 일을 합니다.

지금 하는 방식

  • 공문이 메일·팩스·문자로 제각각 도착
  • 엑셀에 하나씩 옮겨 적음
  • 같은 공문이 다시 와도 눈으로 비교
  • 규격이 바뀐 건 지나치기 쉬움

저희 화면에서

  • 파일을 올리거나 공문 PDF를 넣음
  • 확인이 필요한 건만 목록 위로 올라옴
  • 왜 확인이 필요한지 원본 값과 함께 표시
  • 고치고 승인하면 승인분만 내보내짐

양이 줄었기 때문입니다. 숫자만 비교하면 "변경 없음"으로 넘어갑니다.

DOC-020 · 고수 싸진 것처럼 보임

싸 보이지만 알 수 없습니다. 공급사에 물어봐야 합니다.

두 건 모두 자동으로 넘기지 않고 대기 상태로 보냅니다. 왜 걸렸는지 원본 값을 함께 보여주므로, 담당자는 공급사에 무엇을 물어야 하는지 바로 알 수 있습니다. 필수값이 빠진 건과 같은 공문이 두 번 온 건도 같은 방식으로 걸러냅니다.

차별화 ② 같은 공문이 두 번 와도 잡습니다

재발송 공문과 실수로 두 번 올린 파일은 현장에서 흔합니다. 같은 인상분이 두 번 반영되면 그만큼 돈이 더 나갑니다.

다시 올려도 지우지 않고 쌓습니다

덮어쓰면 이전에 검수하던 내용이 사라집니다. 그래서 쌓아 두고 비교합니다. 같은 파일을 두 번 올리면 두 번째 20건이 전부 중복 의심으로 표시됩니다.

문서 번호가 같아도 내부적으로는 다른 건으로 구분하기 때문에, 검수하던 내용이 섞이거나 사라지지 않습니다.

PDF로 넣은 건과 파일로 올린 건 사이도 비교합니다

가온푸드 공문을 PDF로 읽어 넣은 뒤 20건 파일을 올리면, 같은 내용인 세 건이 중복으로 잡힙니다.

DOC-001 ← 같은 건: 가온푸드 공문 1행
DOC-009 ← 같은 건: 가온푸드 공문 2행
DOC-010 ← 같은 건: 가온푸드 공문 3행

그 공문이 실제로 20건의 원본이었습니다. 입력 경로가 달라도 같은 검사를 거치기 때문에 가능합니다.

차별화 ③ 공문 PDF에서 표를 읽습니다 추가 요건

받은 샘플 공문은 글자가 들어 있는 PDF였습니다. 글자를 읽는 것은 문제가 아니었고, 표의 칸을 되살리는 것이 과제였습니다.

그냥 뽑으면 칸 구분이 사라집니다

그냥 뽑으면  토마토살사S/O4kg/PKPK32,000

저희 결과   토마토살사S/O │ 4kg/PK │ PK │ 32,000

글자마다 위치 정보가 함께 나오는 점을 이용해, 같은 줄에 있는 글자끼리 묶고 가로 위치로 칸을 나눴습니다.

샘플 공문 4종 · 빠뜨린 품목 없음

공문실제읽음
다품목66
가격 일부 누락44
가온푸드33
바다원 재발송11

읽었다고 바로 넣지 않습니다. 표로 보여 주고 고칠 수 있게 한 뒤, 고른 것만 파일·수기와 똑같은 검사를 거칩니다.

4목표와 자체 평가

처음 세운 목표

화면을 예쁘게 만드는 대신 판정의 근거를 보여주는 데 시간을 쓰자. 1인팀이라 욕심을 줄이고, 필수 요건을 확실히 끝낸 뒤 추가 요건에 손대자.

결과적으로 필수 7개를 먼저 끝내고 추가 요건까지 구현했습니다.

막혔던 것과 해결

PDF에서 표가 뭉개짐 — 글자만 뽑으니 칸 구분이 사라졌습니다. 글자의 위치 정보로 줄과 칸을 되살려 해결했습니다.

검수하던 내용이 사라짐 — 파일 읽기에 실패하면 목록이 통째로 비었습니다. 실패해도 기존 목록은 유지하도록 고쳤습니다.

고치고 승인하면 한 번에 안 눌림 — 값을 고친 직후 승인이 먹지 않아 두 번 눌러야 했습니다. 원인을 찾아 한 번에 되도록 고쳤습니다.

자체 평가

된 것 — 제공 20건이 정답표와 전건 일치. 예외 4종을 근거와 함께 표시. 승인분만 내보내기. 공문 PDF 읽기.

못 한 것 — 스캔한 이미지 공문은 읽지 못합니다. 새로운 품목의 이름 정리는 제공 20건에서 만든 사전 범위까지만 보장합니다. 실사용자 테스트는 창업팀 일정(8/21~)에 있어 이번 범위 밖입니다.

안 되는 것은 README에 그대로 적었습니다.

증빙은 브라우저 밖으로 나가지 않습니다. 거래처와 단가가 담긴 자료라 서버로 올리지 않는 구조를 택했고, 배포된 화면에서 전 기능을 써 본 뒤 주고받은 요청을 전부 확인했습니다 — 밖으로 보낸 요청 0건.

부록 A · 창업팀 명세를 고치게 한 문의

1. 실행 결과에서 어긋남을 발견

한 항목의 예외 개수가 명세의 요약표와 규칙 설명에서 서로 달랐습니다. 저희 화면은 규칙 쪽을 따르고 있었습니다.

2. 근거와 함께 문의

추측으로 묻지 않고 실제 실행 결과와 해당 조항을 함께 붙여 "이 둘이 어긋납니다"라고 문의했습니다.

3. 전체 팀 공지로 정정

창업팀이 명세를 고치고 모든 참가팀에 공지했습니다. 저희 화면은 이미 맞아서 고칠 코드가 없었습니다.

창업팀 공지 중
"한 참가팀이 실제 구현 출력과 근거 조항을 함께 보내주셔서 확인됐습니다."

문서를 읽고 만드는 데서 멈추지 않고, 만든 결과로 문서를 검증했습니다.

부록 B · 직접 눌러 보실 순서

로그인이 없습니다. 주소만 열면 바로 쓸 수 있고, 파일이 없어도 예시 데이터로 확인하실 수 있습니다.

#눌러 보실 것확인되는 것

2제공 20건 파일 올리기정답표와 같은 판정. 확인 대상 4건이 이유와 함께 표시됩니다
3확인 필요한 항목 선택왜 걸렸는지, 근거가 된 원본 값과 파일의 그 줄 원문

5승인 → 값을 다시 깨뜨리기승인이 저절로 풀립니다. 잘못된 값이 나가지 않습니다

8JSON · CSV 내려받기승인분만 나갑니다. 어느 파일 몇 행에서 왔는지 함께 실립니다
