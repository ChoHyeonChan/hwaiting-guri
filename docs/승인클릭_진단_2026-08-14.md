# 값을 고치고 승인을 누르면 두 번 눌러야 했던 문제

작성일 2026-08-14 · 원인 규명과 수정 기록

## 증상

적용일이 비어 있어 `확인 필요`로 잡힌 항목에서, 날짜를 채우고 곧바로 `승인`을 누르면
승인되지 않았다. 한 번 더 눌러야 승인됐다. 검수 담당자가 가장 자주 밟는 흐름이라
그대로 두면 시연에서도 그대로 드러난다.

## 첫 번째 진단 — 틀렸다

입력란은 포커스가 빠질 때 값을 커밋한다. 그래서 마우스를 누르는 순간에야 조건이
충족되고, 그때까지 승인 버튼은 `disabled`다. **비활성 버튼이 클릭을 못 받아서**라고
보고 `disabled`를 뗐다.

dev 서버에서는 통과했다. 그런데 배포본에서 다시 확인하니 **여전히 실패하는 경로가
남아 있었다.** 검수 메모를 적고 곧바로 승인을 누르는 경우였다.

## 두 번째 진단 — 이벤트를 직접 찍었다

추측을 멈추고 버튼에 리스너를 걸어 실제 순서를 기록했다.

```
btn mousedown
textarea blur
(mouseup 없음)
(click 없음)
```

**클릭 이벤트 자체가 발생하지 않았다.** `disabled`와는 무관한 문제였다.

일어난 일은 이렇다.

1. 버튼 위에서 마우스를 누른다 → `mousedown`
2. 브라우저가 포커스를 옮기며 입력란에 `blur`를 보낸다
3. `blur` 핸들러가 값을 커밋하고, 목록 전체를 다시 계산한다(예외·중복·상태)
4. 그 결과로 버튼이 **새로 그려진다**
5. 마우스를 뗄 때 `mouseup`을 받은 요소가 `mousedown` 때와 달라진다
6. 브라우저는 이 경우 `click`을 만들지 않는다 → 아무 일도 일어나지 않는다

두 번째 클릭이 먹혔던 이유도 설명된다. 그때는 이미 커밋이 끝나 리렌더가 없었다.

## 왜 dev에서는 통과했나

리렌더가 클릭보다 빨리 끝나면 우연히 동작한다. dev 서버와 프로덕션 빌드는 이 타이밍이
다르다. **타이밍에 기대는 코드였고, dev에서의 통과는 우연이었다.** 이후 검증은
`next start`로 프로덕션 빌드를 띄워 진행했다.

## 수정

포커스 이동과 리렌더의 경합 자체를 없앴다.

- `mousedown`의 기본 동작(포커스 이동)을 막는다 → `blur`가 클릭 도중에 끼어들지 않는다
- 커밋은 클릭 핸들러 안에서 `blur()`로 직접 일으킨다 → 그 자리에서 처리된다
- 그 뒤에 요청을 보낸다 → 커밋된 값을 본 상태에서 판정된다

승인 여부는 화면에서 판정하지 않는다. 클릭 시점의 값은 커밋 직전에 계산된 것이라
방금 채운 조건이 빠져 있다. 판정은 최신 목록을 쥔 쪽에 맡기고 화면은 요청만 보낸다.
승인 함수가 승인 가능 여부를 다시 검사하므로, 버튼을 어떻게 누르든 조건을 못 채운
항목은 승인되지 않는다.

같은 조건에서 같이 겪는 문제라 **승인·반려·재검토·중복 되돌리기** 네 버튼에 모두 적용했다.

## 검증 — 프로덕션 빌드, 그리고 배포본

| 확인한 것 | 결과 |
|---|---|
| 값을 고치고 곧바로 승인(한 번) | 승인 |
| 메모를 적고 곧바로 승인(한 번) | 승인 |
| 값을 고치고 곧바로 반려(한 번) | 반려 |
| 승인 조건을 못 채운 항목에서 승인 | 승인되지 않고 차단 사유가 강조됨 |
| 다른 항목에 갔다 돌아옴 | 강조가 따라오지 않음 |
| 키보드만으로(포커스 후 Enter) | 승인 |

콘솔 오류 0건. 자체 테스트 12섹션·타입 검사·린트·빌드 모두 통과.

## 덤으로 나아진 것

`disabled` 버튼은 Tab 포커스를 받지 못한다. 그래서 이전에는 **키보드만으로는 승인할 수
없었다.** 지금은 포커스가 가고 Enter로 승인된다. 승인 불가 상태는 `aria-disabled`로
알리므로 화면 낭독기도 그 사실을 읽는다.

## 남긴 판단

입력을 실시간 커밋으로 바꾸는 방법도 있었으나 택하지 않았다. 타이핑 중간값이
변경 이력에 쌓이고(`2026-08-2` → `2026-08-21`), 중복 판정이 미완성 품목명으로 돌아간다.
변경 이력은 "누가 무엇을 언제 고쳤는지"를 남기는 검수 근거라, 중간 상태로 채우면
그 의미가 무너진다. 엑셀을 비롯한 데이터 편집 도구가 포커스가 빠질 때 커밋하는 것도
같은 이유다.
