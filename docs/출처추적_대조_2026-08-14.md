# 증빙이 어디서 왔는지 되짚을 수 있는가 — 세 경로 대조

작성일 2026-08-14 · 배포본(`hwaiting-guri.vercel.app`) 실측

## 왜 확인했나

PDF 공문에서 표를 읽는 기능을 붙인 뒤, 읽어 온 항목이 목록에 **`수기`로 표시되는** 것을
발견했다. 값의 근거가 사람의 기억이 아니라 원본 공문인데도 그렇게 기록되고 있었다.

문제는 화면 표시에 그치지 않았다. 내보낸 데이터에도 `input_method: "manual"`,
`file_name: null`로 나가, 받는 쪽이 **어느 공문에서 나온 인상분인지 되짚을 수 없었다.**
CSV로 들어온 항목은 파일명과 행 번호가 남는데 PDF만 그 근거를 잃고 있었다.

원인은 PDF 경로가 수기 등록 함수를 그대로 재사용한 것이었다. 판정 파이프라인을
공유한 것은 의도한 설계지만, 출처 기록까지 함께 묻어간 것은 실수였다.

## 고친 뒤 — 한 목록에 세 출처를 모아 확인

CSV 20건 + PDF 공문 3건 + 수기 1건을 차례로 넣고, 각각을 승인해 내보냈다.

| 항목 | 넣은 방법 | 목록 배지 | 상세 출처 |
|---|---|---|---|
| `DOC-002` | CSV 파일 | `2행` | 파일명 · 3행 (헤더 포함) |
| `GAON-0805-1` | PDF 공문 | `PDF 1쪽` | 공문 파일명 · 1쪽 표에서 읽고 사람이 확인함 |
| `TEL-001` | 화면에서 직접 | `수기` | 화면에서 직접 입력 |

## 내보낸 JSON — 실제 값

승인한 3건을 내려받아 `source_ref`만 뽑았다.

```json
[
  { "doc_id": "GAON-0805-1", "source_type": "PDF",
    "input_method": "pdf",    "file_name": "44_해커톤_OCR샘플_가온푸드_단가변경공문_2026-08-05.pdf",
    "row_no": null, "page_no": 1 },

  { "doc_id": "DOC-002",      "source_type": "XLSX",
    "input_method": "file",   "file_name": "42_해커톤_업로드용_증빙20건_2026-08-04.csv",
    "row_no": 3,    "page_no": null },

  { "doc_id": "TEL-001",      "source_type": "수기",
    "input_method": "manual", "file_name": null,
    "row_no": null, "page_no": null }
]
```

## 여기서 갈리는 두 축

`DOC-002`를 보면 **`source_type`은 `XLSX`인데 `input_method`는 `file`**이다. 둘은 다른 것을
가리킨다.

- **`source_type`** — 증빙이 원래 어떤 형태였는지. 공급사가 엑셀로 보냈다는 뜻이다.
  입력 파일에 적혀 있던 값이고, **검수자가 상세 화면에서 고칠 수 있다.**
- **`source_ref.input_method`** — 그 값이 우리 시스템에 **어떤 경로로 들어왔는지**.
  시스템이 기록하며 사람이 고칠 수 없다.

되짚을 근거로 쓸 수 있는 것은 뒤쪽이다. 앞쪽만 보고 "PDF에서 왔다"고 판단하면,
누군가 표시용 값을 고쳤을 때 근거가 무너진다.

## 행 번호 자리에 쪽 번호를 쓴 이유

CSV의 `row_no`는 파일의 몇 번째 줄인지를 가리킨다. PDF는 줄이 아니라 표의 한 행이라
줄 번호를 붙일 수 없다. 대신 그 표가 있던 쪽을 남긴다. 두 값이 동시에 채워지는 경우는
없고, 수기 등록은 둘 다 비어 있다. **비어 있다는 것 자체가 "사람이 직접 넣었다"는 근거다.**

## 회귀를 막는 장치

자체 테스트 12번에 세 가지를 고정했다.

- PDF로 넣은 항목이 `input_method: "pdf"`로 남고 파일명·쪽 번호를 들고 있는가
- 목록 배지가 `PDF 1쪽` / `수기` / `2행`으로 갈리는가
- 승인 후 내보낸 CSV에 `source_file_name`과 `source_page_no`가 실리는가

`pdf`를 `manual`로 되돌려 실행하면 이 검사 3개가 실패한다. 고친 내용이 테스트로
잠겨 있다는 뜻이며, 실제로 되돌려 실패를 확인한 뒤 원복했다.
